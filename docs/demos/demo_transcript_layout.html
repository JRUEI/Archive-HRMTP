逐字稿：版面、白線、前後跳秒

三個問題各一節。下面的畫面都是照 TranscriptMode.tsx 的實際 class 換算的替身；「現在」的數字是在 dev server（ep10）上量的，提案的數字是這頁打開時直接量替身（未縮放）。

一、加了標記區之後的版面

實際量到的問題：

  • 標記按鈕不在「畫面定位」看得到的範圍。畫面定位會把視窗底邊捲到「字幕群底下的空白」中間（1280×900 下約 y=1264），控制列從 1274 開始，標記區從 1359 開始，所以兩個都在畫面外。邊聽邊標的時候，按鈕永遠看不到，只能靠鍵盤。
  • 手機上控制列 163px、標記區 218px，兩張卡疊起來比字幕群還高。「即時字幕群 (4句)」被擠成兩行，「寫回 Markdown」自己掉到第三行。
  • 還沒有任何標記的時候，標記區只放一句說明和三顆灰掉的按鈕，卻佔 114px（桌機）。

二、字幕往上跳時閃一條白線已確認修好

你已經在 dev server 上確認：改成 transition-[background-color] 之後，字幕往上跳不再閃白線。下面保留當時的原因和前後對照。

  • 字幕群每一列都有 transition-all duration-200（為了 hover 變底色）。
  • 列與列之間的分隔線是 divide-y：除了最後一列，每列底下有一條 1px 線。最後一列的線寬是 0，顏色是預設的 currentColor，也就是字的顏色，深色模式下是白色。
  • 字幕往前推一句時，原本的最後一列變成倒數第二列，要長出分隔線。因為 transition-all，線的顏色會從白色慢慢變成深灰：實測 105ms 時亮度 0.935、184ms 時 0.462、272ms 才到 0.273。所以白線只閃 0.1 秒左右，很難截圖。

修正前　transition-all

修正後　transition-[background-color]

三、前後跳：只有 ±5，還是再加 ±15

四組按鈕放進同一個位置（A 的卡片底部列，本機、有標記鈕），桌機和手機各一張，按鈕都能按，時間會跟著變。最後一組的 Shift 點或按住 0.45 秒＝15 秒。

「可用寬」＝卡片內容寬（桌機 864−40−2＝822，手機 343−32−2＝309）。「同一列」＝前後跳和標記鈕排在同一行。

建議：±5 和 ±15 兩組按鈕，配提案 A

  • ±5 跟 YouTube 的 ← → 一樣，剛好是一兩句話，聽到說話者標錯時倒回去再聽一次最常用。
  • 第二組取 15 不取 10。10 只是按兩下 5，省不了多少；15 是三下，跳過一段長獨白比較有感。YouTube 的 J L 是 10 秒，但那是在影片有焦點時才作用，跟我們的按鈕不衝突。
  • 手機放得下：−15 −5 時間 +5 +15 寬 211px，可用 309，自己一行不會折。放在 A 的底部列時，標記鈕本來就在第二行，沒有多出一行；放在 B 頂部或 C 的精簡標記鈕旁邊，手機會多一行（約 +42px）；D 的固定列會從 52px 變 94px。
  • 不建議 Shift／長按：看不出來有這功能；手機長按會跟系統的選字、放大鏡搶。
  • 鍵盤（焦點在頁面上時）：← → ＝ 5 秒，Shift+← → ＝ 15 秒。不綁 J L，免得同一顆鍵在影片內是 10、在頁面上是 15。
  • 手機沒有鍵盤，所以按鈕要在畫面定位看得到的地方，見第一節的表。前後跳正式站也有，不是只有本機。
