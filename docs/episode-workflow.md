# 集數檔製作流程

每集一個 `content/episodes/epNN.md`，內文依序是 `## 【精簡總結】`、`## 【無損還原】`、`## 【精華片段】`、`## 【完整逐字稿】`。欄位與格式以 `scripts/validate-content.mjs` 為準。
日文自動字幕放在 `content/epNN.ja.vtt`，是逐字稿的來源，也是時間碼的依據。

先做逐字稿，再從逐字稿寫總結與段落：「」裡的字要能在逐字稿裡原文找到。

## 逐字稿

```markdown
[12:34.5] [福嶋晴菜] 這一列的中文
```

- 照字幕逐句翻成繁體中文，不摘要、不補充；えー、あの 這類口頭禪可以不翻。字幕聽錯的字照上下文更正（例如「福島な」是福嶋晴菜）。
- 一列一個說話者，照句子切，一列不超過 60 字；換人就換列。
- 時間碼是這一列第一個字在字幕裡的時間，一律 `mm:ss`（超過一小時分鐘繼續往上數）。照順序遞增，相鄰兩列不重複：同一秒開始的兩句併成一列，換人的話後一列往後挪一秒。整秒寫好再補 0.1 秒（見下）。
- 說話者只用 `福嶋晴菜`、來賓全名（跟 front matter 的 `guest` 一樣）、兩人同時說的 `福嶋晴菜＆來賓全名`，以及現場有出聲的 `工作人員`。不用「兩人」「音效」「環境音」。
- 聲音標記只寫字幕有的，放在該列文字裡，不單獨成列：`[笑い]` 寫 `[笑聲]`、`[泣き声]` 寫 `[哭聲]`、`[息をのむ音]` 寫 `[吸氣]`、`[咳払い]` 寫 `[清喉嚨]`、`[ため息]` 寫 `[嘆氣]`、`[叫び声]` 寫 `[尖叫]`、`[大歓声]` 寫 `[歡呼]`，`[鼻息]`、`[拍手]` 照寫。`[音楽]` 是自動字幕偵測到的背景音樂，不寫。
- 唸來信、唸投稿的部分放在「」裡，跨列時每列各自成對；信裡再引用的話用『』。來信開頭寫 `書籤名「X」さん寄來的，謝謝。`（第 5 回決定しおり之前是 `筆名`），信尾的「〜とのことです」寫成 `」信上這麼寫。`。
- 用語照 `docs/GLOSSARY.md`：節目名『はるまとぺーじ』、簡稱はるまとぺ、問候こんまとぺ、聽眾稱呼しおり；集數一律「第 N 回」。ラジオネーム譯「筆名」，しおりネーム譯「書籤名」。
- 固定譯法：こんにちは譯「你好」，お嬢様譯「千金」，主持人的暱稱寫福ちゃん，書籤的量詞用「張」。
- 人名、筆名、書籤名寫日文原文，不寫羅馬拼音；敬稱照原文留 さん、ちゃん、くん，不改成先生、小姐、醬、桑（猜不出性別，也不是原文）。
- 同一位聽眾各回寫法要一致。字幕常把書籤名聽錯：先對 `docs/GLOSSARY.md` 的常客表，再跑 `npm run glossary:dry-run -- --input content/epNN.ja.vtt` 看字幕裡有哪些已知的誤聽。聽不出來、別回也對不上的寫「……」，不猜。
- 不加譯註。只有雙關、謎題非看日文不可時，寫成「日文（中文）」，例如「はなたば（花束）」。作品名用《》，節目單元名用『』。

寫好整秒時間碼之後，用日文字幕補上 0.1 秒：

```powershell
node scripts/stamp-times.mjs epNN
```

- 時間碼變成 `[mm:ss.d]`（例如 `[12:34.5]`），整秒那段不動。字幕疊層照小數換列；列表、段落、精華只顯示整秒，段落與精華的時間碼也照舊寫整秒。
- 小數是 YouTube 自動字幕的開口時間，捨去到 0.1 秒；怎麼挑字寫在 `scripts/stamp-times.mjs` 開頭。有來賓的回字幕多是一個片語一個片語出現，從片語中間開始的列找不到字，留整秒（約一成），不算錯。
- 工具不改已經有小數的列。改了某列的整秒，先把它的小數拿掉再跑。
- 小數不動整秒，所以整秒本身就晚的列（換人往後挪一秒的那種）補了小數也還是晚。

## 精簡總結

- 4～5 點，照播出順序，每點 40～100 字，不用粗體（圖卡直接印原文）。
- 第一點會放在首頁卡片上、只露出兩行：寫這一回是誰、主軸是什麼。

## 標題

front matter 的 `title` 寫這一回 2～3 個話題，用「、」和「與」接起來，例如「聽眾的名字しおり、問候語こんまとぺ與冰淇淋撲克」。有來賓的回以來賓全名開頭。不用驚嘆號，不寫回數。

## 段落格式

```markdown
### [12:34] [標籤] 標題

* **小標**：這一段講到的內容
```

`[12:34]` 是這一段開始的那一列逐字稿的時間碼。條列每段 3～5 點，每點寫成 `* **小標**：內容`，小標 2～8 字。段落裡不放 `>` 引言，精華句寫在【精華片段】。

「」裡的字要能在逐字稿裡原文找到（可以只取一列裡連續的一段，不能跳著接）；轉述不加引號。其他敘述只寫逐字稿講到的事：不加逐字稿沒有的語氣與動作（「笑說」只在附近有 `[笑聲]` 時用），不補因果、不誇大，保留「好像、大概、可能」這類保留語氣。主持人寫「福嶋」，來賓寫姓。

## 切段規則

各集段數要能互相比較，所以每集都照同一套規則切，不看當集內容多寡調整粗細。

1. 一段＝一個話題對象：一件事、一個物件、一個人、一個作品、一封來信，或單元裡的一題、一則投稿。同一個大主題底下換了子題，也算換話題。
2. 話題對象換了，而且新話題講滿 60 秒（看逐字稿時間碼，剛好 60 秒也算），才開新段。
3. 同一件事的延伸細節不開新段。不到 60 秒的插話或短話題併進前一段；連續好幾個短話題也一樣全併進前一段。
4. 來信一封一段，標籤照內容下。連續幾封各自不到 60 秒，併成一段 `[來信]`。
5. 單元照題目或投稿分段，標籤一律 `[單元]`，標題寫成 `『單元名』：這一段的重點`（例：`『ミステリーハルストーリー』：第 2 題`）。單元開頭的說明不到 60 秒，併進第一題。
6. 段落照播出順序排，不跨時間合併。隔一陣子又回到先前的話題，就在那個時間點另開一段，標籤沿用；所以相鄰兩段可以同標籤。
7. 開場和結尾各算一段，不受 60 秒限制。結尾從「福嶋晴菜的『はるまとぺーじ』第 N 回，到了尾聲的時間。」那列開始，到逐字稿最後一列，不再切。
8. 條列只寫這一段時間範圍內講到的內容。

### 分界落在哪一列

新段從「大半在講新話題」的那一列開始。一列前後講兩件事時，比兩邊的字數（不算標點）：差不多就歸字多的那邊，完全一樣就留在前一段。「那麼下一題」「下一張書籤」這類轉場列歸新段；節目名那列「福嶋晴菜的『はるまとぺーじ』。」歸前一段，新段從它後面開始。

## 精華片段

網站「精華」分頁和推廣素材都從這裡來。每集 3～5 段，照播出順序，不重疊。

```markdown
### [12:34–14:05] 標題
> 段內某一列的原文
- 起 [12:34] 話題怎麼開始
- 鋪 [12:50] 怎麼一步步推到笑點
- 收 [13:41] 笑點之後怎麼收
```

- 起＝第一列的時間碼，迄＝最後一列的「下一列」的時間碼；片段就是 `起 <= 時間 < 迄` 的那些列。
- 精華句是段內某一列的原文（可只取一列裡連續的一段），不加「」。標題講笑點的鋪陳，不劇透結論。
- 起鋪落收：落＝精華句那一列，不另外寫；網站照時間把四拍排成一張表，落那列就是精華句。`- 起` 的時間＝片段開頭，`- 鋪`、`- 收` 寫那一拍開始那列的時間碼，要 起 < 鋪 < 落（精華句那列）< 收 < 迄。
- 落就是最後一列時沒東西可收，只寫起、鋪；落就是第 2 列時沒東西可鋪，只寫起、收。其他情況三行都要寫。
- 每拍一句話講完，一來一往用 → 接；寫法跟段落條列一樣（「」裡的字要在逐字稿找得到、不加逐字稿沒有的事）。

挑哪段：有笑點或收尾、鋪陳也在段內、沒聽過節目的人也看得懂、有來賓的回兩人都有參與（個人回就挑主持人自己的哏）、同一集不挑重複的話題。長度不設上限，超過 3 分鐘時看看是不是其實兩個哏，是就拆開或只留一個。

怎麼切：
- 第一列不能在接上一句：不以「對、是的、是啊、原來、而且、所以、還有、不過、但是、可是、就是、然後、那種、確實、也是」起頭（前面帶「啊、欸、嗯」也算），往前找到話題真正開始的那列；需要來信當鋪陳就從唸信那列開始。
- 最後一列要收在 。或 ！（聲音標記不算），不停在問句或半句。

## 標籤

節目結構：

| 標籤 | 用在 |
|---|---|
| 開場 | 節目名、問候、自我介紹、來賓介紹，到第一個話題之前 |
| 結尾 | 收播前的告知與道別 |
| 來信 | 連續幾封各自不到 60 秒的來信併成的一段 |
| 單元 | 『ハルマトペ研究所』『ミステリーハルストーリー』『青春裁判所』『カジノメールイン』等節目單元 |
| 告知 | 節目中段的宣傳：作品、活動、商品、FANBOX、下回來賓 |

內容（閒聊與講滿 60 秒的來信）先沿用既有的，同義詞不另開：

| 用這個 | 用在 | 不用 |
|---|---|---|
| 節目 | 這個節目本身：節目名、Logo、問候語、聽眾稱呼、はるまとぺノート | 幕後、企劃、節目秘辛 |
| 近況 | 最近發生的事、生活 | 日常、生活、近況報告 |
| 美食 | 吃的喝的 | 飲食、甜點、料理 |
| 作品 | 自己或來賓參與的作品：角色、舞台、朗讀劇、動畫 | 舞台劇、舞台幕後、工作 |
| 活動 | 活動本身：生日活動、祭典、聯名 | 活動回顧、聯名回顧 |
| 回憶 | 過去的事、學生時期 | 過去、母校 |
| 人際 | 來賓或別人的事、兩人的交情 | 友誼、人物、前輩 |
| 遊戲 | 電玩、桌遊、益智遊戲 | 時間小偷 |
| 解謎 | 謎解き活動與這個興趣本身（單元裡的謎題用 `單元`） | 謎解き、街頭解謎 |
| 方言 | 關西腔、三河腔 | 方言話題、口音 |
| 雜談 | 以上都不合的話題 | 閒聊、聊天、喜好 |

```powershell
# 看目前用過哪些標籤
Select-String -Path content\episodes\*.md -Pattern '^### \[[^\]]+\] \[([^\]]+)\]' -Encoding utf8 | ForEach-Object { $_.Matches[0].Groups[1].Value } | Group-Object | Sort-Object Count -Descending
```

## 檢查

```powershell
npm run validate:content -- --strict
```

算錯誤、會擋部署的：front matter 缺欄位或格式不對；少了四個區塊之一或順序不對；精簡總結不是 4～5 點，或有一點不在 40～100 字；段落標題不是 `### [mm:ss] [標籤] 標題`、標籤不在上表、時間碼沒有比上一段晚或對不到逐字稿任何一列；條列不是 3～5 點、不是 `* **小標**：內容`、小標不是 2～8 字；段落裡有 `>`；精華片段不是 3～5 段、不是 `### [mm:ss–mm:ss] 標題` 加下一行 `>`、起訖對不到逐字稿的列、重疊或倒序、第一列在接上一句、最後一列沒收在 。！、起鋪收少寫或順序不對、起不等於片段開頭、時間不是 起 < 鋪 < 落 < 收 < 迄、某拍對不到逐字稿的列；「」或精華句的字在逐字稿裡找不到；說話者不在名單內。

只出警告、不擋部署，但也要清到零（`--strict` 會把警告當錯誤）：標題用驚嘆號；段落不到 60 秒；相鄰兩列同一秒（不看小數）、時間倒退、整列重複；只有聲音標記沒有文字的列；清單外的聲音標記；超過 60 字的列；用到小姐、先生、桑、醬、第 N 集、栞名或括號裡的羅馬字。
